Lymors Lycommons Library Documentation

🚀 Introduction

Lymors Lycommons is a comprehensive Android utility library designed to accelerate development by providing commonly needed functionality out of the box. Built with modern Android development practices, it offers extensive extension functions, utilities, and managers that simplify everyday Android development tasks.

📋 Key Features

🔧 Extension Functions

  • Context Extensions: Toast, permissions, networking, device info, app settings
  • View Extensions: Animations, PDF generation, click handlers, visibility control
  • String Extensions: Encryption, validation, QR codes, compression, TTS
  • Data Extensions: JSON parsing, date operations, bitmap utilities
  • Activity/Fragment Extensions: Navigation, status bar, screenshots, flash control

🗄️ Data Management

  • Authentication: Email, Google, Phone auth with Firebase
  • Database: Firestore & Realtime Database operations
  • Storage: Firebase Storage with WorkManager background uploads
  • ViewModels: Reactive state management with StateFlow
  • DataStore: Modern data persistence with coroutines

🛠️ Utilities & Managers

  • Permission Helper: Runtime permission handling
  • Location Manager: GPS and network location
  • Notification Manager: Local notifications
  • Dialog Utilities: Common dialog patterns
  • Media Player: Audio playback with lifecycle awareness

🎯 What This Library Solves

❌ Common Development Pain Points

  • Writing boilerplate code for everyday operations
  • Managing complex Firebase authentication flows
  • Handling background file uploads reliably
  • Creating consistent UI animations and interactions
  • Managing app permissions and device features
  • Working with dates, JSON, and data validation

✅ Lycommons Solutions

  • One-line operations: Complex tasks reduced to single method calls
  • Built-in best practices: Error handling, null safety, coroutine support
  • Consistent API: Unified naming and parameter patterns
  • Type safety: Generic extensions with proper type handling

📦 Installation & Setup

🔧 Requirements

  • Android SDK: Minimum SDK 21 (Android 5.0)
  • Target SDK: Recommended SDK 34 (Android 14)
  • Kotlin: 1.8.0 or higher
  • Gradle: 8.0 or higher
  • AndroidX: Latest stable versions

📥 Step 1: Add the Library

Option A: Local Module (Recommended for Development)

This is the easiest way to use the library during development. The library module is already part of your project.

// In your settings.gradle.kts or settings.gradle
include ":app"
include ":mylib"

// In your app's build.gradle.kts or build.gradle
dependencies {
    implementation(project(":mylib"))
    
    // Other dependencies...
    implementation(libs.androidx.core.ktx)
    implementation(libs.androidx.appcompat)
}

Option B: Using AAR File (For Distribution)

To use the library as an AAR file in other projects:

Step 1: Build the AAR file from this project:

# In the project root directory
./gradlew :mylib:assembleRelease

# The AAR will be generated at:
# mylib/build/outputs/aar/mylib-release.aar

💡 Quick Build: Run the provided build-aar.bat script for Windows or use the manual commands above.

⚠️ Note: Building the full AAR with all dependencies may require resolving Gradle configuration issues. If the build fails, you can:
  • Try building with ./gradlew :mylib:assembleDebug instead
  • Temporarily disable complex dependencies (Firebase, Hilt, Glide) in build.gradle.kts
  • Use the manual approach below for immediate distribution

Alternative - Manual AAR Creation: If Gradle build fails, you can manually create a distributable package:

# Copy the library source files to your target project
mkdir -p /path/to/target-project/libs/mylib/
cp -r mylib/src/main/java/* /path/to/target-project/libs/mylib/

# Create a simple JAR or ZIP file
cd mylib/src/main/java
zip -r ../../../libs/mylib-source.zip .

# Then in your target project, copy the source files to your app module

Step 2: Copy the AAR to your target project:

# Create libs folder in your app module if it doesn't exist
mkdir -p app/libs

# Copy the AAR file
cp mylib/build/outputs/aar/mylib-release.aar /path/to/your-project/app/libs/

⚠️ Important: When using AAR files, you must manually add all the library's dependencies to your project (listed in Step 2 below).

🔧 Troubleshooting

❌ "Unresolved reference" errors

Solution: Make sure you've added the library as a dependency and synced Gradle. For local modules, ensure the module path is correct in settings.gradle.

❌ Firebase services not working

Solution: Ensure you've added the google-services.json file to your app module and applied the Google Services plugin in your build.gradle.

❌ ProGuard/R8 issues in release builds

Solution: Add the ProGuard rules mentioned above. If issues persist, add -keep class com.lymors.lycommons.** { *; } to keep all library classes.
